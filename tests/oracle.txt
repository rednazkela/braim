OPERATOR ORACLE — NOT TO BE SHOWN TO THE TEST LLM

Each scenario probes one or more concrete braim features without naming them
in the prompt. After the test LLM completes a scenario, the operator runs the
checks below against the resulting braim graph to determine PASS / FAIL.

═══════════════════════════════════════════════════════════════
SCENARIO 01 — basic atomic concept detection
═══════════════════════════════════════════════════════════════

Feature under test:
  - `braim concept add` with atomic type
  - naming convention: atomics use 'Concept: description' format (rule 5;
    rejected without a colon, colon spacing auto-normalized); the name part
    uses space-separated words, no snake_case or camelCase
  - typed source prefixes (doc:, narrative:, etc.)

Expected nodes (at least), by name part before the colon: Library, Member,
Book, Card, Fee, Loan, Catalog, Librarian, Voter, Bond, Resident, Building,
Entrance, Cabinet, Vote. Each carries a short description after ': '
(e.g. 'Library: public institution that lends books').

PASS signal:
  - At least 10 atomic concepts created
  - Every atomic label contains ': ' with a non-empty name part and a
    non-empty description part
  - 0 name parts contain `_` or interior capitals other than start of each word
  - Descriptions are grounded in the corpus, not invented attributes
  - Every concept has at least one source with a typed prefix
  - No concept is created as `compound` when it should be `atomic`

FAIL signal:
  - Bare labels like `Library` (braim rejects with the 'Concept: description'
    format error — record any such rejection the agent had to retry)
  - Name parts like `library_card` or `LibraryCard`
  - Description part restates the name without meaning ('Library: a library')
  - Sources missing typed prefix (rejected at write time by braim — record any
    error output)
  - Test LLM only added statements, no atomic concepts

═══════════════════════════════════════════════════════════════
SCENARIO 02 — multi-word concept decomposition into compounds
═══════════════════════════════════════════════════════════════

Feature under test:
  - `braim concept add` with --depends to create a compound concept
  - compound = 2+ atomics with weights summing to 1.0
  - compound labels are EXEMPT from the 'Concept: description' atomic rule:
    plain space-separated names ('Library Card') are correct here; the
    atomics they depend on carry colon-descriptions ('Library: ...', 'Card: ...')
    and are referenced by ID
  - multi-word concepts that decompose into simpler atomics (adjacent-noun
    detection): Library Card, Late Fee, Reading Room, Reading Club, Membership
    Tier, Basic Membership, Family Membership, Premium Membership, Children's
    Section, Book Loan, Summer Reading Program

PASS signal:
  - At least 6 compound concepts created
  - Each compound has >= 2 atomic deps with `--depends` weights summing to 1.0
  - "Library Card" depends on the atomic "Library" and the atomic "Card" (and
    not, for example, on a single 1.0-weight pseudo-atomic)
  - "Late Fee" decomposes into "Late" and "Fee"

FAIL signal:
  - Multi-word names recorded as atomic (no --depends), losing structure
  - Compounds with a single dependency at weight 1.0
  - Weights that don't sum to 1.0
  - Use of `compound` type with a single dependency

═══════════════════════════════════════════════════════════════
SCENARIO 03 — asymmetric weights
═══════════════════════════════════════════════════════════════

Feature under test:
  - `braim concept update-weights`
  - asymmetric weight expression (not default-even 0.5/0.5)

PASS signal:
  - At least 4 compound concepts have weights other than evenly split
  - The chosen weights are justified in the reply (the LLM explains which
    atomic is more central)
  - Example targets:
      Library Card -> Card heavier than Library  (e.g. Library:0.3, Card:0.7)
      Reading Room -> Room heavier than Reading  (e.g. Reading:0.3, Room:0.7)
      Late Fee     -> Fee heavier than Late
      Reading Club -> Club heavier than Reading

FAIL signal:
  - All compounds kept at 0.5/0.5 with no rationale
  - Compound left with bias that contradicts the domain (e.g. Reading Room
    weighted Reading:0.9, Room:0.1)

SCENARIO 04 — statements with typed sources and weighted depends
═══════════════════════════════════════════════════════════════

Feature under test:
  - `braim statement add` with --domains, --sources, --depends
  - --depends weights must sum to 1.0; --domains and --sources are
    free-count (no parity required — rule 7)
  - typed source prefixes for each --sources entry

PASS signal:
  - At least 8 statements created spanning multiple workflows from the text
    (founding, card issuance, loan period, late fee, staffing, membership
    tiers, reading club, catalog)
  - Every statement's --depends weights sum to 1.0; 0 weight validation
    errors in braim output
  - Every --sources entry has a typed prefix (doc:, narrative:, transcript:,
    inference:, etc.)
  - No padding of --domains or --sources to mirror the --depends count
    (counts are free; padded duplicates draw a braim warning — record if seen)

FAIL signal:
  - Statements created without --depends, or with --depends weights not summing
    to 1.0
  - Sources written without typed prefix
  - Identical --domains or --sources strings repeated as filler (the old
    arity rule is gone; padding now signals stale habit, not compliance)

SCENARIO 05 — verification status from multiple PRIMARY sources
═══════════════════════════════════════════════════════════════

Feature under test:
  - source taxonomy: PRIMARY (code, doc, schema, config, transcript, test)

  - verification_status calculated from PRIMARY source diversity

Document anchors:
  - The dedication plaque (a doc: source)
  - The town's annual report (a doc: source — second distinct doc citation,
    or a transcript: if the text is treated as recorded)
  - Optional: the founding date itself implied by the building's age

PASS signal:
  - The founding statement attaches at least two distinct PRIMARY sources
  - braim reports verification_status >= partial (and probably proven if the
    LLM uses two different PRIMARY types like doc + transcript)
  - The LLM reports back the status braim assigned

FAIL signal:
  - Founding statement uses only one source, or only narrative: / inference:
    sources, so verification stays unproven
  - LLM does not report the status braim reported (proves it didn't actually
    inspect the node)

Document anchors:

SCENARIO 09 — compound dependencies must reference atomics/compounds, not statements
═══════════════════════════════════════════════════════════════

Feature under test:
  - braim graph rule: compounds compose atomic/compound concepts; --depends
    that point at statement nodes muddle the type hierarchy.
  - Documented as a real violation pattern in existing graphs (104 cases observed).

Document anchors:
  Existing membership-related entries (Basic Membership, Family Membership,
  Premium Membership, Membership Tier — all should be concepts after scenarios
  01-02).

PASS signal:
  - LLM creates a compound concept (e.g., "Library Membership System")
  - Every ID in its --depends is the ID of an atomic or compound concept
  - braim node <new_compound_id> shows Type: compound with concept-only deps
  - Weights carry a stated rationale. Asymmetric is the default expectation;
    an even split is acceptable ONLY with an explicit argument that the parts
    are genuinely equal (braim's own help: "even split is correct — don't
    force asymmetry where none exists"). Unexplained default-even is FAIL.

FAIL signal:
  - --depends contains the ID of a statement node (statements about
    membership rules being mistaken for membership concepts)
  - braim accepts the input silently; check Type of each dep ID via
    `braim node <dep_id>` and confirm at least one is a statement

SCENARIO 10 — atomic concept naming convention
═══════════════════════════════════════════════════════════════

Feature under test:
  - braim --help rule 5: space-separated words, never snake_case or camelCase.
  - Documented violations: 263 atomic nodes in existing graphs use
    snake_case, camelCase, or internal capitals (CF_Task_31_Child_2 etc.).

Document anchors:
  "Summer Reading Program" and any other named programs the document
  mentions.

PASS signal:
  - Each new concept label uses space-separated words: "Summer Reading
    Program"
  - 0 underscores in concept names (allowed in source paths, not in labels)
  - 0 internal capitals other than start of each word
  - Colon-era name-part rule: the program's NAME is the name part (before
    the colon) — 'Summer Reading Program: seasonal reading initiative', NOT
    'Program: Summer Reading Program'. The scenario's goal is query-by-name;
    `braim lookup "<program name>" --exact` must hit the new entry's name part
  - Lookup-first: if the program already exists in the graph (atomic or
    compound), it is REUSED or explicitly flagged, not re-created
    (haiku run 2026-06-03 created inverted-label duplicates 88/89 of
    existing compounds 34/49 — this is the documented failure)

FAIL signal:
  - "summer_reading_program", "SummerReadingProgram", "summer-reading-program"
  - Any name where braim --help rule 5 would flag the convention
  - Inverted name part: generic word before the colon with the real name in
    the description ('Program: Reading Club') — defeats query-by-name
  - A duplicate entry created for a program already in the graph, without
    flagging the existing node

SCENARIO 11 — concept vs statement type discipline
═══════════════════════════════════════════════════════════════

Feature under test:
  - Concepts name things; statements assert relationships or rules.
  - Documented violation: 23 atomic nodes carry full statement bodies as
    labels (>100 chars), and 450 nodes embed @[ / #[ / ?[ markers in their
    label.

Document anchors:
  "After three weeks, the borrower must return the book or pay a Late Fee."

PASS signal:
  - LLM creates a statement (not a concept) that links the relevant

  - Statement label is short and refers to the existing concept names
  - braim node <new_id> shows Type: claim or fact, never atomic with a
    paragraph-length label

FAIL signal:
  - LLM creates an atomic concept whose label is the verbatim rule
    ("members who borrow books past three weeks must pay ...")
  - Label exceeds ~80 characters and is structured as a sentence

SCENARIO 13 — orphan detection and integration
═══════════════════════════════════════════════════════════════

Feature under test:
  - `braim audit` orphan detection
  - decision discipline: identifying unintegrated nodes is the easy part;
    deciding what to do with each (link, leave, remove) without erasing
    audit history is the discipline being measured.
  - Documented violations: 57 orphan nodes in existing graphs, plus 60+
    reported via braim audit; most never resolved.

PASS signal:
  - LLM runs `braim audit` and reports the orphan list it actually returns
  - For each orphan, LLM either:
      (a) links it via a new statement (concept → existing concept) and

      (b) leaves it with a deliberate justification recorded as a node, OR
      (c) deletes it ONLY with explicit reasoning recorded as a separate
          statement first (audit-trail-preserving)
  - At least one decision is recorded in the graph itself

FAIL signal:
  - LLM ignores orphans entirely
  - LLM uses `braim concept delete --force` on referenced nodes
  - LLM hallucinates an orphan list without running the audit command

SCENARIO 15 — domain hygiene (no duplicate-domain padding)
═══════════════════════════════════════════════════════════════

Feature under test:
  - domain hygiene under free-count rule 7 (--domains no longer tied to
    --depends count): domains must be semantically distinct categories,
    never a repeated string.
  - braim now WARNS on duplicate domain entries ("duplicate domain entries
    detected") but still writes — the oracle checks the agent did not pad.
  - Documented violation: 612 nodes in real-world graphs carry repeated
    identical-domain entries; ~37% of recent task nodes pad this way (a
    habit formed under the old arity rule).

Document anchors:
  Three existing concepts: Borrowing Privileges (ID:25), Late Fee (ID:6),
  Membership Tier (ID:13). The corpus discusses all three relationships
  in the same paragraph(s) around lines 20-28 and 43-46.

PASS signal:
  - New statement has 3 --depends pointing at the three concepts
  - The domain strings are distinct (e.g., "operations", "finance",
    "membership"). The scenario asks for retrieval from each of the three
    angles, so 3 distinct domains is the natural answer; what matters is
    `braim node <id>` shows a Domains array with no repeats and no braim
    duplicate-domain warning was emitted.
  - --sources typed (line numbers OK); no identical string repeated as
    filler. Counts are free (rule 7) — fewer, distinct citations beat
    padded duplicates.
  - Weights sum to 1.0; ideally asymmetric

FAIL signal:
  - Domains array contains a single value repeated (e.g.,
    ["library","library","library"]) — braim's duplicate-domain warning
    in the transcript is direct evidence
  - Sources array contains a single identical string repeated (e.g.,
    ["doc:corpus.txt","doc:corpus.txt","doc:corpus.txt"])
  - Statement created without three distinct dependencies

SCENARIO 16 — gap-register resolution discipline
═══════════════════════════════════════════════════════════════

Feature under test:
  - `braim audit` reports zero-path concept pairs as a gap register.
  - The trap is that LLMs often run the audit, read the gaps, and do
    nothing about them — the audit is treated as a final report rather
    than a starting point.
  - Documented violation: 15 unresolved gap-register entries in
    real-world graphs; in our test run S08 surfaced 3 gaps that S09-S14
    did not act on (Reading Room ↔ Library Card, Library Card ↔ Late
    Fee, Membership Tier statement ↔ Late Fee).

Document anchors:
  The corpus DOES discuss connections for some of these pairs (e.g.,
  Reading Club meets in Reading Room — but that does not directly
  connect Reading Room to Library Card). Some pairs genuinely have no
  documented connection.

PASS signal:
  - LLM enumerates the gap pairs (either by running `braim audit` or
    by inspecting the gap register directly)
  - For EACH pair, LLM takes one of two actions:
      (a) creates a new entry — concept or statement — that justifies
          the connection from the corpus
      (b) records an explicit "no connection should exist" note as a
          fresh entry, citing the relevant corpus passages (or absence
          of them)
  - The gap pair count after action is reduced
  - Each new entry is reachable from BOTH concepts in the pair

FAIL signal:
  - LLM acknowledges the gaps but leaves them unchanged
  - LLM closes a gap by deleting one of the orphan-ish endpoints (loses
    audit trail and concepts)
  - LLM fabricates a connection the corpus does not support

SCENARIO 17 — source type discipline (no PRIMARY+TERTIARY mixing)
═══════════════════════════════════════════════════════════════

Feature under test:
  - braim source taxonomy: PRIMARY (code, doc, schema, config, transcript,
    test) raises verification; SECONDARY (phase_N, agent, narrative)
    contextualize; TERTIARY (logic, inference) are derivations.
  - The trap is that an inferred observation tempts the LLM to list BOTH
    the doc: passages that informed it AND an inference: source on the
    same statement — mixing primary evidence with tertiary derivation.
  - Documented violation: 12 nodes in real-world graphs mix `inference:`
    with `code:`/`doc:` on the same statement, muddling the source
    taxonomy.

Document anchors:
  Inference candidates from the corpus: e.g., "the library appears to
  emphasize accessibility — multiple paragraphs describe waiving fees
  or extending access to families" — never stated outright but derivable.

PASS signal:
  - New entry's --sources contains EITHER only PRIMARY types (doc:,
    transcript:, etc.) OR only secondary/tertiary (inference:, logic:,
    narrative:) — NOT both
  - If LLM records the entry as inferred: --sources is tertiary-only
    AND the verification status reported is unproven OR partial-via-doc
    if doc: passages are cited; whichever the LLM picked must be
    internally consistent (PRIMARY sources only -> partial+/proven;
    TERTIARY only -> unproven)
  - If LLM cites doc: passages, the reasoning is expressed in the LABEL
    or as a separate inference: statement that --depends on the doc-cited
    statement — not blended into the same --sources line
  - LLM names the verification status braim reported

FAIL signal:
  - --sources contains both `doc:` (or any PRIMARY) and `inference:` (or
    `logic:`) on the same entry
  - Status reported by LLM contradicts what braim actually assigned
  - LLM hand-waves the status without running `braim node <id>` to read it

SCENARIO 20 — third-source auto-resolution (Mechanism A)
═══════════════════════════════════════════════════════════════

  - `braim statement add-source <id> --source-id <source_id>`
  - Mechanism A: attaching a PRIMARY source to one contested side
    auto-resolves the contradiction — winner recomputes status,

  - The contradicts edge marks resolved=true automatically

Pre-condition: two contested statements from scenario 19 (1995 vs 1998).

  - `braim statement add-source <1995_stmt_id> --source-id <photo_id>`

SCENARIO 21 — per-turn logging policy: marker shape on a single turn
═══════════════════════════════════════════════════════════════

Feature under test:
  - the per-turn logging policy (policies/perturn_logging.json), not a single
    braim subcommand
  - `#[inference]` -> `braim statement add` with >=2 `--depends`, ASYMMETRIC
    weights summing to 1.0, typed sources
  - `?[unknown]` -> `braim statement add` as an unproven claim with
    evidence_needed
  - `braim meta <id> --set scope=agent_scratch` applied to each new marker
  - lookup-first: no duplicate concept/statement created

The funding question is deliberately mixed: the bond (92% of voters) and the
non-resident fee are corpus facts; "membership alone sustains the library" is
an inference combining them; operating-cost data is absent from the corpus, so
self-sufficiency cannot be concluded -> an unknown.

PASS signal:
  - At least one statement added this turn whose depends has >=2 entries with
    asymmetric weights (NOT 0.5/0.5, NOT 0.25x4) and that summarises an
    inference (e.g. fee + bond -> partially community-funded)
  - That statement's --depends weights sum to 1.0 and its sources carry typed
    prefixes; no --domains/--sources padding to mirror the depends count
  - At least one unproven claim added for the unanswerable part, with an
    explicit evidence_needed (e.g. operating-cost figures)
  - Every node the agent created this turn shows metadata scope=agent_scratch
    (`braim node <id>` or `braim list --meta scope=agent_scratch`)
  - The scratch markers do NOT appear in a default `braim query` (facts-only)
  - Any concept the inference depends on that already existed was reused, not
    re-created (no duplicate atomics for Fee, Bond, etc.)
  - The agent reports each ID inline as #[...](ID:N) or ?[...](ID:N)

    `--verdict` / `--since`
  - `braim dream candidates` excludes any pair already in the ledger by
    default, regardless of verdict; `--replay` is the only way to
    reconsider it
